### Root cause of remaining failure

`vertex_scalar_d` uses float64 for the final sum but the contractions
`mode_n_contract` inside are still float32 SGEMM:

```cpp
// vertex_scalar_d (simplified):
upcast_f2d(psi → dbl_a)           // float32 → float64 ✓
for each bond:
    upcast_f2d(msg → dbl_msg)      // float32 → float64 ✓  
    mode_n_contract_d(dbl_a, dbl_msg → dbl_b)  // float64 GEMM ✓?
sum(dbl_a) → double               // float64 sum ✓
```

The issue: `mode_n_contract` for messages contracts chi×chi matrices.
At chi=400, even with float64, the contraction chain:
  ψ[chi,chi,chi,D] × M0[chi,chi] × M1[chi,chi] × M2[chi,chi] × O[D,D]
produces intermediate results that underflow float64 (< 2.2e-308).

The product of 3 messages each with λ_min ≈ 1e-4 gives:
  ψ × (1e-4)^3 = ψ × 1e-12 per channel
For chi=400 channels all at 1e-4: sum ≈ 400 × 1e-12 = 4e-10 — fine.
But if Vidal messages are not diagonal in practice (BP residuals), the
cross terms add coherently and the intermediate tensors can underflow.

### The real fix: chi→vector message refactor

**Why chi×chi is wrong**: Messages are stored as chi×chi matrices but
the diagonal BP path only uses the diagonal. Off-diagonal elements are
zero (normalize_and_delta zeroes them). So we store chi² floats but
only chi carry information.

**What changes**:
- Messages stored as chi-vectors (diagonal entries only)
- vertex_scalar: contract ψ × diag(λ) per bond = simple scaling
- edge_scalar: Ze = dot(λ_a, λ_b) = O(chi) dot product, no SGEMM
- pseudo_sqrt: already diagonal, no change needed

**The math**:
Current: Ze = Tr(M_a · M_b) = Σ_{ij} M_a[i,j] × M_b[i,j]
With diagonal: Ze = Σ_i λ_a[i] × λ_b[i] = dot(λ_a, λ_b)

Current: vertex = ψ contracted with all bond M[chi×chi]
With diagonal: vertex = ψ contracted with all bond diag(λ) = ψ scaled per index

**Why this fixes the precision**:
- No chi×chi SGEMM → no float32 precision loss in contractions
- dot(λ_a, λ_b) in float64: exact, no underflow
- ψ × diag(λ): each element scaled by one λ_k, no accumulation

## Plan of Action

### Step 1: Add chi-vector message storage

Option A (minimal): keep chi×chi buffer but only read/write diagonal.
  - No memory layout change
  - vertex_scalar uses only diagonal entries
  - Backward compatible

Option B (full): change message buffer to chi floats per bond.
  - Halves message memory from chi² to chi per bond×direction
  - Requires changing all message indexing
  - Larger change, more memory efficient

**Recommended: Option A first** — validate correctness, then optimize.

### Step 2: Update vertex_scalar to use diagonal

New `vertex_scalar_diag`:
```cpp
// Contract ψ with diagonal messages — scale each index by λ_k
// Much cheaper than full chi×chi contraction
for each bond d:
    scale_mode_n(ψ, diag_msg[d], chi_d, mode_d)  // O(chi × volume)
// Sum over all remaining indices
return sum(ψ)  // in float64
```

### Step 3: Update edge scalar

```cpp
// Ze = dot(λ_a, λ_b) — O(chi) in float64
Ze = 0.0
for i in range(chi):
    Ze += msg_from_a[i*chi+i] * msg_from_b[i*chi+i]  // read diagonal
```
