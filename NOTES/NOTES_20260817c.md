## Topic: Root Cause of Chi Saturation Failure — BP Message Conditioning

## Key Finding: BP Off-Diagonal Noise at Large Chi

### The Full Picture (Algorithm from Paper §2.5)

1. **After each gate**: message stored as `diag(λ_k/‖λ‖)` — diagonal, Vidal-normalized.
   Code: gate.hpp line 766: `msg[i+i*new_chi] = std::max(hS[i]/snorm, 0.f)`
   Messages ARE in the correct Vidal gauge after gate application. ✓

2. **During BP sweep** (`full_bp=false`, diagonal path):
   - Contracts site tensor with neighbor messages
   - Computes chi-vector `d_mu` (marginal over all bonds except cut bond)
   - Stores normalized vector back in diagonal of chi×chi message matrix
   - Result: message is approximately diagonal but NOT exactly — numerical
     errors from SGEMM/SGEMV accumulate off-diagonal elements

3. **Before next gate** (`pseudo_sqrt`):
   - Takes the chi×chi message matrix (supposed to be diagonal)
   - Calls `rocsolver_ssyevd` to eigendecompose it
   - Computes sqrt and inv_sqrt of eigenvalues
   - At chi=400: off-diagonal noise from 100 BP sweeps makes the message
     matrix ill-conditioned → eigendecomposition is unreliable

### Why Chi=200 is Stable

At chi=200, 100 BP sweeps produce off-diagonal noise of O(1e-6) per element.
The 200×200 matrix has condition number manageable by ssyevd.
`pseudo_sqrt` produces clean sqrt/inv_sqrt.

### Why Chi=400 Collapses at Saturation

At chi=400, 100 BP sweeps accumulate more off-diagonal noise (larger matrices,
more SGEMM operations, more numerical diffusion). When chi FIRST hits 400
(saturation), two things happen simultaneously:
1. Chi grows from ~380 to 400 in one step — BP must now handle 400×400 matrices
2. Off-diagonal noise is amplified by the larger matrix size
3. ssyevd on a poorly conditioned 400×400 matrix → wrong eigenvalues
4. pseudo_sqrt produces wrong environment → gate applies wrong transformation
5. psi tensor corrupted → n(v,t) spreading → C(t) collapse

### Evidence

- sum(n(v,t)) jumps from ~0.0085 to ~0.012 at collapse — normalization broken
- 60/68 sites non-zero at collapse vs 54 at previous step — unphysical
- BP takes 74s at collapse (100 sweeps, not converging) — confirms divergence
- Pattern: collapse at EXACTLY the step chi first hits chi_max, for any chi_max > ~200

## What the Code Does (gate.hpp)

```
Gate application:
  1. absorb_env: ψ_v × sqrt(μ_e→v) for all neighbor bonds e
     Uses pseudo_sqrt which calls ssyevd on chi×chi message
  2. QR: cv_i = Q_i R_i
  3. Bond matrix: RR = R_1^T R_2
  4. Gate: R̃ = G(RR)
  5. SVD: R̃ = U S V^T, truncated to new_chi
  6. Reconstruct: cv_i^new = Q_i M_i where M1=U√S, M2=√S V^T  (symmetric!)
  7. deabsorb_env: cv × inv_sqrt(μ_e→v) for all neighbor bonds
  8. Store message: diag(S[i]/‖S‖) — diagonal Vidal gauge
```

The gate IS implementing the Vidal/symmetric gauge correctly (steps 6, 8).
The problem is step 1 (absorb_env) which uses pseudo_sqrt on BP-modified messages.

## What BP Does (measures.hpp)

```
BP sweep (full_bp=false, diagonal path):
  For each bond direction:
    1. Contract ψ_v with all neighbor messages except cut bond
    2. Sum over all indices except chi of cut bond → chi-vector μ
    3. Normalize μ → store in diagonal of messages[bond_msg]
    
Result: messages are CHI-VECTORS stored in diagonal of chi×chi matrix.
After 100 sweeps: off-diagonal elements accumulate from SGEMM roundoff.
At chi=400: off-diagonal noise large enough to destabilize ssyevd.
```

## Three Potential Fixes (in order of invasiveness)

### Fix 1: Reduce BP sweeps + enforce diagonal (least invasive)
After each BP sweep, zero the off-diagonal elements of the message matrix.
Since BP diagonal path only writes to diagonal, off-diagonals are pure noise.
Zeroing them costs O(chi²) per bond but eliminates the conditioning problem.

```cpp
// After normalize_and_delta: zero off-diagonal elements
zero_off_diagonal<<<blocks, 256>>>(messages[msg_idx], chi);
```

### Fix 2: Store messages as chi-vectors not chi×chi matrices
Messages from the diagonal BP path are chi-vectors conceptually.
Storing them as chi×chi wastes memory and introduces spurious off-diagonal noise.
Requires changing message buffer layout — larger change but cleaner.

### Fix 3: Symmetric gauge with diagonal-only BP
Keep messages strictly diagonal throughout. BP updates only the diagonal.
pseudo_sqrt becomes trivial (just sqrt of diagonal elements, no ssyevd needed).
This is the full symmetric gauge approach — most correct but largest change.
