# Session Notes — 2026-08-17

## Topic: Chi Maximization via Lightcone Calibration

---

## Core Philosophy Established

**The key insight**: for a fixed memory budget, lightcone-allocated chi_large produces
better C(t) than full-allocated chi_small, because the chi budget is concentrated
where it matters — the interior sites where truncation error lives.

Outside-lightcone sites:
- Should be exactly zero by causality (Trotter frontier)
- In full allocation: O(1e-4 to 1e-5) numerical leakage from BLAS roundoff
- Waste chi budget on sites that contribute only noise to C(t) and inner products
- Lightcone allocation eliminates this: exact zero, cleaner C(t), better MPF

## New Implementations

### 1. BP sweep skip for outside-lightcone bonds (measures.hpp)

Added `if (bond.chi_alloc == 1) continue` to:
- `bp_update`: main BP sweep per bond
- `bp_update_norm`: norm BP sweep
- Bethe partition function bond loops (contributes log(1)=0)

**Distinction** (important):
- chi=1 at FRONTIER (inside lightcone, chi_alloc=chi_max): BP MUST run
  — messages carry real information, chi will grow to chi_max
- chi=1 OUTSIDE lightcone (chi_alloc=1): BP skip — trivial identity messages

Always use `chi_alloc` for skip decisions, never `chi` (runtime value).

### 2. --state flag in main_pauli_sweep

`--state=NL` or `--state=NL,N1,N2` — runs only specified states.
Default: all 4 states (backward compatible).

**GPU pool workflow (3 GPUs)**:
```bash
ROCR_VISIBLE_DEVICES=0 ./main_pauli_sweep CHI N_STEPS CUT --state=NL > log_NL.log &
ROCR_VISIBLE_DEVICES=1 ./main_pauli_sweep CHI N_STEPS CUT --state=N1 > log_N1.log &
ROCR_VISIBLE_DEVICES=2 ./main_pauli_sweep CHI N_STEPS CUT --state=N2 > log_N2.log &
wait
ROCR_VISIBLE_DEVICES=0 ./main_pauli_sweep CHI N_STEPS CUT --state=N3 > log_N3.log
cat log_NL.log log_N1.log log_N2.log log_N3.log > combined.log
```
MPF scripts work unchanged on combined.log.

Benefit: each state gets full GPU chi budget. At chi=400, NL alone uses ~58%
of 32GB — 4x larger than sharing 4 states at chi=200 (35%).

## Chi Maximization Protocol (run_chi_sweep.sh)

### Step 1: Reference run
- Largest chi that fits in GPU memory for NL state only
- Full allocation (no lightcone)
- Measures: C(t), PAULI weights, timing
- This is ground truth for the topology/Hamiltonian

**Heavy-hex NL memory estimates (1 state, 32GB GPU)**:
| chi | Workspace | State | Messages | Total | % of 32GB |
|-----|-----------|-------|----------|-------|-----------|
| 200 | 257 MB | 2081 MB | 24 MB | 2362 MB | 7% |
| 300 | 865 MB | 6987 MB | 55 MB | 7907 MB | 25% |
| 400 | 2051 MB | 16517 MB | 97 MB | 18665 MB | 58% |
| 450 | 4004 MB | 26542 MB | 122 MB | ~30 GB | ~94% |

**Recommended: chi=400 (58% VRAM, safe)**

### Step 2: Frontier calibration
- Run NL only at chi=10,20,30,50,70,100 (cheap, seconds each)
- Measure actual max_shell at last cycle using measure_vhop.py
- Stop when max_shell converges across two consecutive chi values
- Output: chi_frontier (minimum chi for faithful frontier measurement)
- Output: v_hop_eff (actual velocity, not slope — use for --v_hop)

**Critical rules**:
- Pre-flight chi must NOT saturate during the run
  (chi saturated = wave starved = v_hop underestimated)
- measure v_hop for the SAME n_steps as the production run
- Use max_shell/n_steps (actual), not linear slope (underestimates)

### Step 3: Production run (3 GPUs)
- chi_prod = chi_ref (or larger if VRAM allows with lightcone saving)
- --v_hop from Step 2 (shared frontier, MPF-safe)
- NL+N1+N2 parallel on 3 GPUs, N3 sequential
- Total wall-clock ≈ 2x one state

### Step 4: Compare
- C(t) reference (full, NL, chi_ref) vs production (lightcone, all states)
- If production C(t) agrees: lightcone is lossless for that chi/n_steps
- If production C(t) differs: frontier was too tight (increase chi_frontier)

## Validated Results

### BP skip speedup at chi=70, 10 cycles, shared frontier:
Step 5 cumulative: 1.99s (before) → 1.68s (after) = **15% faster**
C(t) identical to before skip.

### Memory: chi=400, NL only vs chi=200, 4 states:
- chi=200, 4 states: ~35% VRAM
- chi=400, NL only: ~58% VRAM
- But chi=400 >> chi=200 → significantly less truncation error

### Leakage outside lightcone grows with cycles:
- 10 cycles: NL max leakage ~1e-5
- 20 cycles: NL max leakage ~7.8e-5
- Physical: BLAS roundoff accumulates per cycle per BP sweep
- Lightcone allocation eliminates this by construction
